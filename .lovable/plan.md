## Problem\n\nOn `/owner/crm/relationships`, the segmented tab triggers (Brokerages · Clients · Developer Registry) have a contrast issue when active. The page sets `data-[state=active]:bg-black data-[state=active]:text-white text-black`, but the base `TabsTrigger` component already injects `data-[state=active]:text-foreground` (which resolves to black in this monochrome theme). Because both `text-white` and `text-foreground` are state-active variants with equal specificity, CSS source order decides — and the base style often wins, producing black text on a black background. The result is the active tab looks like a black bar with no readable label.\n\nPer `mem://ui-ux/visual-standards/segmented-control-tab-standard`, active segmented tabs must be high-contrast on light surfaces (white text on solid black, or black text on white).\n\n## Fix\n\nUpdate the three `TabsTrigger` elements in `src/pages/CRMRelationships.tsx` (lines 717–719) to force the active foreground/background with explicit, higher-priority classes that override the base `text-foreground`:\n\n- Add `!text-white` (with `!` important modifier) on the active state\n- Keep `data-[state=active]:bg-black`\n- Keep inactive state as `text-black hover:bg-black/5`\n- Add a subtle hover state for inactive triggers so they read as interactive\n\nFinal per-trigger class:\n```\ndata-[state=active]:bg-black data-[state=active]:!text-white text-black hover:bg-black/5 rounded-lg px-5\n```\n\nThis guarantees white labels on the black active pill regardless of base-component CSS order.\n\n## Verification\n\n- Visit `/owner/crm/relationships` after the change.\

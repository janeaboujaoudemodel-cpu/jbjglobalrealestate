
# Backend Contrast Audit & Fix — Emerald Surface Lock

Goal: eliminate every remaining black text / black icon on emerald surface across the entire backend (owner panel → all department hubs → settings), then prove it with per-page, per-section screenshots.

## 1. Route inventory (full backend sweep)

Enumerate every authenticated backend route from `src/routes/*` + `src/pages/owner/**`, `src/pages/developer-hub/**`, `src/pages/broker-portal/**`, `src/pages/executive/**`, plus settings. Target set (expanded from the existing `scripts/contrast/backend-emerald-audit.mjs`, which only covers 3 routes):

- `/owner`, `/owner/audit`, `/owner/crm`, `/owner/crm/*` (leads, deals, contacts, accounts, pipelines, reports, inbox)
- `/owner/developers`, `/owner/developers/new-project`, `/owner/developers/:id`
- `/owner/projects`, `/owner/properties`, `/owner/listings`
- `/owner/hr`, `/owner/hr/*`, `/owner/finance`, `/owner/finance/*`
- `/owner/marketing`, `/owner/content`, `/owner/media`
- `/owner/operations`, `/owner/legal`, `/owner/compliance`
- `/owner/analytics`, `/owner/reports`, `/owner/audit`
- `/owner/settings`, `/owner/settings/*` (profile, team, roles, integrations, notifications, billing, security)
- `/developer-hub/*`, `/broker-portal/*` backend equivalents

The final route list is generated by scanning route files, not hand-picked, so no page is missed.

## 2. Automated contrast scanner (upgraded)

Extend `scripts/contrast/backend-emerald-audit.mjs` into `scripts/contrast/backend-full-sweep.mjs`:

- Auth via `LOVABLE_BROWSER_SUPABASE_*` env (owner session).
- For each route: wait for network idle, then walk every element under any emerald surface selector:
  - `[data-surface="emerald"]`, `[data-backend-icon-tile="emerald" | "emerald-soft"]`
  - `.jj-emerald-metallic`, `.jj-pill-emerald-metallic`, `.jj-surface-emerald`, `.jj-cta-emerald`, `.jj-emerald-action`, `.jj-emerald-solid`, `.jj-emerald-fill`
  - `.jj-icon-tile-emerald`, `.jj-chip-emerald`, `.jj-side-tile`
  - Any element whose computed `background-color` resolves to the emerald hexes (`#064E3B`, `#032A1E`, `#042C1C`, `#011B13`) or the metallic gradient tokens
- Fail any descendant where:
  - Text `color` / `-webkit-text-fill-color` ≠ `rgb(255,255,255)` (with allow-list for hairline gold `#B89555` on chips)
  - SVG `stroke` / `fill` ≠ white / none / transparent
- Skip nested light surfaces (`data-surface="champagne|cream|light|page|gold"`, `.jj-card-inner`, `.jj-emerald-soft`, `.jj-emerald-outline`).
- Also scan hover / focus / active pseudo-states by dispatching `mouseover` + `focus` on interactive descendants (fixes the "black on hover" class of bugs).
- Output: `/mnt/documents/backend-contrast-sweep/<timestamp>/`
  - `results.json` — per-route failure list with selector, computed color, class, text sample
  - `<route>.png` — full-viewport screenshot
  - `<route>__<section>.png` — element-level screenshot for every failing node and every emerald surface (button, icon tile, pill, sidebar item, header control, badge)
  - `report.md` — human-readable index

## 3. Fix strategy (source of truth: CSS, not per-file overrides)

All contrast fixes land in the shared CSS contract, not sprinkled inline utilities:

- `src/index.css` — emerald surface descendant locks: `[data-surface="emerald"] *`, `.jj-emerald-metallic *`, `.jj-pill-emerald-metallic *`, `.jj-cta-emerald *`, `.jj-icon-tile-emerald *`, `.jj-side-tile *` → `color: #fff !important; -webkit-text-fill-color: #fff !important;` and matching `svg { stroke: currentColor; fill: none; color: #fff; }` where appropriate.
- `src/pages/owner/crm/shell/crmTokens.css` — sidebar / header emerald locks (already partly defined; extend to cover `:hover`, `:focus-visible`, `[data-state="active"]`, `[aria-selected="true"]`).
- Add explicit hover/active variants so no interaction can flip text or icons to `#1A1A1A` / `currentColor` inheriting from a parent dark token.
- Any component that hard-codes `text-[#1A1A1A]` or `text-black` while sitting inside an emerald surface gets switched to a semantic class (`jj-on-emerald`) that resolves to white. Only edit component files where the CSS-level lock cannot reach (e.g. inline SVG `stroke="#000"`).
- No new colors, no palette drift — white on emerald is the only allowed pairing per the locked ombre-emerald standard in memory.

## 4. Validation loop (no "assumed fixed")

1. Run `backend-full-sweep.mjs` → capture baseline failures per route.
2. Apply CSS/token fixes.
3. Restart preview, rerun sweep.
4. Loop until every route reports `badCount === 0` AND hover/focus pass.
5. For every emerald surface on every route, take an element-level screenshot (`locator.screenshot`) — buttons, icon tiles, pills, sidebar rows, header controls, badges, tab strips, breadcrumbs, KPI cards, empty-states, modals, dropdowns (opened via click), toasts (triggered where feasible).
6. Manual visual pass: open each screenshot, confirm no black glyph on emerald. Any ambiguous case is re-shot at 2× zoom via `locator.screenshot`.
7. Publish the proof folder path in the final reply and attach the `report.md` summary (routes × surfaces × pass/fail matrix, all green).

## 5. Deliverables

- Updated `scripts/contrast/backend-full-sweep.mjs`
- CSS/token edits in `src/index.css` and `src/pages/owner/crm/shell/crmTokens.css` (+ minimal component edits only where CSS cannot reach)
- Proof artifact: `/mnt/documents/backend-contrast-sweep/<timestamp>/` with full-page + per-surface screenshots and `report.md`
- Short written summary listing routes audited, count of surfaces checked, count of fixes applied, and final `badCount = 0` confirmation

## Out of scope

- Public/marketing routes (already covered by other contrast workflows)
- Palette changes, layout changes, feature changes — contrast only
- Extraction / wizard / preview-card work from previous turns (untouched)

## Technical notes

- Scanner uses Playwright + the injected Supabase session; no credentials logged.
- Fixes prefer the descendant CSS lock pattern already used for `.jj-cta-emerald` so future components inherit correctness by default.
- Screenshots kept under `/mnt/documents/` per sandbox rules; nothing written to project tree except the new script.



## Analysis

After reviewing the codebase, here's what exists and what needs to change:

### Already implemented
- Google sign-in (via `supabase.auth.signInWithOAuth` — needs migration to Lovable Cloud managed auth)
- Biometric/Face ID sign-in (`useBiometricAuth` hook + WebAuthn)
- OTP email system (`send-email-otp` + `verify-email-otp` edge functions)
- Welcome email (`send-welcome-email` edge function)
- Password change confirmation email (`send-password-change-confirmation`)
- Confirm password field (only on reset mode — missing from signup)

### What needs to change

**1. Social Login — Google + Apple (Facebook not supported)**

Facebook OAuth is not available on this platform. Google and Apple are the two supported providers. The current Google sign-in uses `supabase.auth.signInWithOAuth` directly — this must be migrated to `lovable.auth.signInWithOAuth()` via the managed Lovable Cloud solution.

- Call `configure-social-auth` tool for Google and Apple
- Update `Auth.tsx` to import from `@/integrations/lovable` and add Apple sign-in button
- Remove the direct `signInWithGoogle` from AuthContext (replace with lovable module calls in the Auth page)

**2. Confirm Password field on Signup**

Currently the confirm password field only shows on `mode === "reset"`. It must also show on `mode === "signup"` and validation must enforce matching passwords.

- File: `src/pages/Auth.tsx`
- Show confirm password input when `mode === "signup" || mode === "reset"`
- Add password match validation in `validateForm()` for signup mode

**3. Password save / autocomplete support**

The current `<Input>` fields don't have proper `autocomplete` attributes. Adding `autocomplete="new-password"` (signup/reset) and `autocomplete="current-password"` (signin) enables browser password managers and Face ID autofill on iOS Safari.

- File: `src/pages/Auth.tsx`
- Add `autoComplete="email"` on email input
- Add `autoComplete="current-password"` on signin password, `autoComplete="new-password"` on signup/reset password fields
- Add `name` attributes for proper form detection

**4. Welcome email with credentials on signup**

The existing `send-welcome-email` edge function already sends a branded welcome email. It needs to be enhanced to include:
- "You have successfully created your account"
- The user's email (for reference)
- A note: "Save this email for anytime you need to sign in"
- The password must NOT be included in email (critical security violation — passwords must never be transmitted or stored in plaintext). Instead, the email will say "Your password is the one you chose during registration. For security, we never store or send passwords in emails."

File: `supabase/functions/send-welcome-email/index.ts`

Also: ensure `Auth.tsx` calls `send-welcome-email` after successful signup.

**5. OTP-based password reset flow**

The existing OTP infrastructure (`send-email-otp` + `verify-email-otp`) can be used for password reset instead of the current "send reset link" approach. The flow:
1. User enters email on forgot password screen
2. System sends OTP via `send-email-otp`
3. User enters 6-digit OTP code
4. System verifies via `verify-email-otp`
5. On success, show new password + confirm password fields
6. Use `supabase.auth.admin.updateUserById` via a new edge function to set the password

New edge function needed: `reset-password-with-otp` — accepts email + verified OTP token + new password, uses service role to update the user's password.

File changes:
- `src/pages/Auth.tsx` — add OTP input step between "forgot" and "reset" modes
- New mode: `"verify-otp"` added to `AuthMode`
- `supabase/functions/reset-password-with-otp/index.ts` — new edge function

### Security notes
- Passwords will NEVER be sent in emails — this is an industry-standard security requirement
- The welcome email will include the user's email address and a reminder to save their chosen password
- OTP codes expire in 10 minutes with rate limiting (already implemented)
- Password reset via OTP uses server-side verification before allowing password change

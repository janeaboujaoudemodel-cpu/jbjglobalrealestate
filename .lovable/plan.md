

# Session 8 — Export / Download / Print / File Validity Fix

## Root Cause Analysis

### SVG Invalid XML (TASK 2)
The export page's `downloadSVG()` at line 385 creates a blob directly from `tintedSvg` — which is the raw `design.svg_source` from the database with color replacements applied. This SVG was originally generated by `generateOfficialStampSVG()` and may contain:
- `data-stamp-element` custom attributes (not valid SVG namespace attributes — browsers show XML parse error)
- Missing `xmlns` declaration (the function only checks via string `.includes()` which can miss edge cases)
- Missing or malformed `viewBox` attribute
- Stale `filter` references from `inkMode` processing in `StampSVGRenderer` that got baked into saved SVGs

The wizard's `getPreviewSvg()` (line 422) serializes from the DOM via `XMLSerializer`, which picks up React `useId()`-scoped IDs (e.g., `r1a-clipPath`) injected by `StampSVGRenderer` — these scoped IDs are only meaningful in the current render and break when opened standalone.

### PNG Export Fails (TASK 1)
`svgToPng()` at line 39 uses `btoa(unescape(encodeURIComponent(svg)))` to create a data URL. If the SVG contains invalid XML, the browser's image decoder rejects it silently (`img.onerror` fires). The error is caught but shows only a generic toast.

### PDF Export Fails (TASK 3)
`svgToPdf()` at line 110 calls `svgToPng()` internally — so it cascades from the PNG failure. Additionally, `pdfDoc.embedPng()` can fail if the PNG blob is malformed.

### Print Preview Shows Black (TASK 4)
The print handler at line 1096-1108 writes raw `tintedSvg` into a new window's `<body>`. Issues:
- No `width`/`height` on the SVG element → browser renders at 0×0 or default
- No `@page` size CSS → page margins clip the content
- The SVG may reference `url(#...)` filter/clip-path IDs that don't exist in the new document context
- Background defaults to browser's print stylesheet which can be dark on some systems

### Download Flow Glitchy (TASK 5)
`triggerDownload()` creates/removes DOM anchor elements. When called rapidly in sequence (e.g., manufacturer export calls it twice back-to-back at lines 454-457), this causes visible DOM flicker. The `setTimeout(() => URL.revokeObjectURL(url), 1000)` cleanup can race with slow downloads.

## Implementation Plan

### 1. Create `sanitizeSvgForExport()` utility

New function in `StampExportPage.tsx` (and importable by wizard):

```typescript
function sanitizeSvgForExport(svg: string, size?: number): string {
  let s = svg;
  // 1. Ensure xmlns declarations
  if (!s.includes('xmlns="http://www.w3.org/2000/svg"'))
    s = s.replace('<svg', '<svg xmlns="http://www.w3.org/2000/svg"');
  if (!s.includes('xmlns:xlink') && s.includes('xlink:'))
    s = s.replace('<svg', '<svg xmlns:xlink="http://www.w3.org/1999/xlink"');
  // 2. Strip data-* attributes (not valid SVG)
  s = s.replace(/\s+data-[a-z-]+="[^"]*"/gi, '');
  // 3. Ensure viewBox exists
  if (!/viewBox=/.test(s)) {
    const sz = size || 200;
    s = s.replace('<svg', `<svg viewBox="0 0 ${sz} ${sz}"`);
  }
  // 4. Ensure width/height for standalone rendering
  if (!/\bwidth="/.test(s)) s = s.replace('<svg', '<svg width="100%"');
  if (!/\bheight="/.test(s)) s = s.replace('<svg', '<svg height="100%"');
  // 5. Add XML declaration for file validity
  if (!s.startsWith('<?xml'))
    s = '<?xml version="1.0" encoding="UTF-8"?>\n' + s;
  return s;
}
```

### 2. Job Offer → real HR-grade structured template (and same upgrade pattern for the others)

Today the AI just gets a one-paragraph prompt and free-forms a letter. Replace with a deterministic, A4-ready HTML composer that the AI only fills paragraphs into — never structure. This is what makes it premium AND fast (less AI tokens, predictable layout).

For Job Offer, the rendered body becomes a single-page A4 letter with:
- Date (auto today, editable).
- Recipient block (name, ID, address if given).
- Subject line: "Offer of Employment — {jobTitle}".
- 2-paragraph warm intro generated by AI.
- **Terms of Employment table** (1-column key/value, gold hairline borders, champagne header row): Position, Department, Reporting To, Start Date, Probation Period, Working Hours, Annual Leave, Notice Period, Base Salary, Allowances, Benefits.
- **Commission Structure table** (multi-row): each row = label + rate + payout trigger + notes. Owner adds as many rows as they want (default rows pre-seeded for brokers: "Direct deals" and "Company-sourced leads"). **Empty rows are skipped at render time** — fill it, it shows; leave it blank, it disappears.
- **Custom fields section** (the user's "always give me options to add field" request): an "Add field" button on the left form lets the owner type any label and value (e.g. "Sign-on bonus", "Car allowance"). Each non-empty custom field renders as another row in the Terms table.
- 1-paragraph AI closing (acceptance instructions).
- **Signature block** (locked layout, always renders, at bottom of page):
  ```
  For JBJ GLOBAL REAL ESTATE                  Accepted by Applicant
  ┌──────────────────┐  ┌─────────┐           ┌──────────────────┐
  │  owner signature │  │  stamp  │           │ applicant signature │
  └──────────────────┘  └─────────┘           └──────────────────┘
  Name: ____________________                  Name: ____________________
  Title: Owner / Director                     ID:   ____________________
  Date: {today}                               Date: ____________________
  ```
  Owner's signature + stamp come from the existing asset library (auto-attach the defaults). Applicant side stays blank — it's printed for hand-signing or e-sign later.

The AI's job shrinks to "generate the 3 narrative paragraphs only" → fast (~1-3s), and 100% premium structure every time.

### 3. Roll the same pattern to every template
Each template in `documentCatalog.ts` gets a `composer` function: deterministic HTML for letterhead-adjacent structure (tables, parties, clauses, signature block, dynamic custom fields), AI fills only the narrative parts. Specifically:
- Employment Contract → numbered clauses block + Terms table + signature block.
- Warning Letter → incident table + corrective-action table + signature block (HR + employee).
- NDA → parties + numbered clauses + dual signature block.
- Commission Agreement → multi-row commission table (same composer as Job Offer's) + signature block.
- Internship Agreement → terms table + signature block.
- HR Letter → simple letter + signature block.
- Partnership / Referral, Custom Letter → letter + signature block.
- Client templates (Form A / F / I, PAA, Tenancy Addendum, Custom Client) → property + parties tables + signature block.

All composers always emit a single-page A4 sheet. Multi-page only happens when content actually overflows; we never pad with empty pages.

### 4. Multi-page control (the "1 page unless I decide" rule)
Studio topbar gets a small "**Pages: 1 ▾**" selector (1, 2, 3, "Auto / fit content"). Default = 1. If the content overflows the selected page count, we shrink the body's CSS scale to fit; the user can bump pages up if they want it bigger. Already runs at A4 (816 × 1056 px @ 96dpi) — we enforce the same A4 height in print/PDF/DOCX export so what you see is what gets generated.
